# 쇼츠 제작 자동화 — 편집자 없이 만드는 방법, 장단점, 구현 설계

> 문서 묶음: [쇼츠 문제 분석·해결방안](shorts-analysis.md) · **쇼츠 제작 자동화**(이 문서)
> 작성 기준일: 2026-11-15 · 상태: **설계 완료, 코드 미구현**

## 0. 요약

**답: 가능합니다. 이 채널 형식은 자동화하기 좋은 편입니다.** 쇼츠 대부분이 "원장 단독 출연 + 진료실 배경 + 큰 노란 자막 + 25~40초"(표본 확인)라서, 편집자가 하는 일 중 컷 편집·자막·세로 맞춤·제목 초안·업로드는 기계가 할 수 있습니다.

다만 **두 가지는 사람이 남아야** 합니다.

1. **기획**(무엇을 말할지, 첫 2초 훅): 편집자가 편집하면서 메우던 재미를 촬영 전 대본 카드로 옮깁니다.
2. **최종 승인**(의료광고 책임): 자동으로 만든 제목·자막에 과장 표현이 섞일 수 있으므로 원장 또는 담당자가 5~10분 보고 승인합니다.

| 방법 | 요약 | 권장 |
| --- | --- | --- |
| A. 상용 도구 (Vrew·CapCut 자동 자막, OpusClip류 롱폼→쇼츠 자동 추출) | 오늘 바로 시작, 사람이 도구를 직접 다룸 | 단기 대안 |
| B. 자체 파이프라인 (이 리포 기술: Whisper + ffmpeg + 로컬 AI) | 업로드하면 초안 완성, 브랜드 템플릿·측정 연동 | |
| **C. B + 사람 검토 (반자동)** | B로 초안 90%, 사람은 검토·승인만 | **권장** |
| D. AI 아바타·음성 합성 (촬영도 생략) | 원장 촬영 없이 생성 | 비권장 (신뢰·법적 위험) |

권장 진행: **1단계(2주) 세로 촬영본 → 자동 자막·컷·제목 초안 → 검토 화면 → 파일 받아 수동 업로드**. 2단계에서 롱폼 → 쇼츠 자동 추출, 3단계에서 예약 업로드와 성과 수집까지 붙입니다.

## 1. 편집자가 하는 일 나누기

이 채널 쇼츠 한 편을 만드는 작업을 쪼개고, 자동화할 수 있는 정도를 매겼습니다.

| 작업 | 자동화 | 방법 | 사람 몫 |
| --- | --- | --- | --- |
| 기획·대본 | △ 보조 | AI가 주제 후보·대본 초안 제안(성과 데이터·댓글 질문 기반) | 주제 선택, 원장 말투로 다듬기 |
| 촬영 | ✗ | — (원장이 찍음). 한 번에 여러 편 몰아 찍기 + 자동 분할로 부담 줄임 | 촬영 |
| 컷 편집 (무음·말 더듬음·NG 제거) | ○ | 음성 인식의 단어별 시간 + 무음 감지 | 검토 화면에서 구간 확인 |
| 자막 (받아쓰기·줄 나누기·타이밍) | ○ | Whisper(이미 01에서 운영 중) + 의료 용어 사전 교정 | 오탈자 확인 |
| 강조 자막·상단 훅 문구 | △ | AI가 핵심어 표시·훅 3안 제안, 채널 스타일 템플릿 | 1안 선택 |
| 세로(9:16) 맞춤 | ○ | 세로 촬영본은 그대로, 롱폼은 얼굴 위치 따라 잘라냄 | — |
| 배경음·음량 | ○ | 라이선스 있는 음원 폴더에서 선택, 음량 표준화·말할 때 낮춤 | — |
| B-roll·이미지·효과음·밈 | ✗~△ | 템플릿 범위(제품 사진 카드 등)만 | 필요하면 직접 |
| 제목·설명·해시태그 | ○ | AI 초안 + 설명란 템플릿(영상 코드·UTM 자동) | 선택·수정 |
| 의료광고 표현 점검 | △ | 규칙 사전 + AI 2차 점검 → 경고 표시 | **승인 (필수)** |
| 업로드·예약 | ○ | YouTube Data API (§4.7) | — |
| 관련 동영상 연결 | △ | API 지원 미확인 → 업로드 후 Studio에서 수동 체크 | 10초 |
| 성과 수집 | ○ | YouTube Analytics API → 주간 표 | 주간 리뷰 |

→ 편집자 몫 중 기계적인 부분(컷·자막·세로·음량·업로드)은 거의 다 자동화됩니다. 남는 것은 **판단**(훅, 리듬, 재미 요소)이고, 이 설계는 그 판단을 **촬영 전(대본 카드)과 촬영 후(검토 5~10분)로** 옮깁니다.

## 2. 방법별 장단점

### A. 상용 도구로 사람이 직접 편집

Vrew(국산, 한국어 자동 자막·무음 컷), CapCut(자동 자막·템플릿), OpusClip·Vizard류(롱폼에서 쇼츠 구간 자동 추출·세로 맞춤).

| 장점 | 단점 |
| --- | --- |
| 개발 없이 오늘 시작 | 결국 사람이 도구를 매번 조작 — "편집자 없음"이 아니라 "편집이 쉬워짐" |
| 한국어 자막 품질 검증됨(Vrew) | 영상 단위 수작업이 남아 편수가 늘면 다시 병목 |
| 템플릿·효과 풍부 | 영상·음성이 외부 서버로 올라감 (환자 출연분은 특히 주의) |
| | 측정(영상 코드·UTM·성과 표)과 따로 놂 — 분석 보고서의 S2·S7을 손으로 맞춰야 함 |
| | 월 구독료, 도구 정책·가격 변경에 종속 |
| | 롱폼→쇼츠 추출 도구의 한국어 구간 선택 품질은 직접 시험 필요 |

### B. 자체 파이프라인 (이 리포 기술 재사용)

| 장점 | 단점 |
| --- | --- |
| 원본을 올리면 초안이 자동으로 나옴 — 사람이 도구를 만지지 않음 | 개발 2~6주 + 유지보수 |
| 이미 가진 것 재사용: Whisper(01에서 24초 녹음 → 약 1.7초), 로컬 AI(02의 Ollama), 서버 PC GPU(RTX 2080) | 창의적 편집(밈·효과음·B-roll)은 템플릿 수준에 머묾 |
| 영상이 서버 PC 밖으로 나가지 않음(로컬 AI 선택 시) | 로컬 소형 AI(qwen3 4B)는 한국어 제목·훅 품질이 아쉬울 수 있음 → Claude API 선택지(자막 텍스트만 전송) |
| 채널 고유 스타일(노란 자막 등)을 템플릿으로 고정 → 일관성 | 템플릿이 하나뿐이면 영상이 다 비슷해짐(분석 보고서 P5 반복 피로) → 템플릿 여러 개 순환 필요 |
| 측정 연동: 영상 코드·UTM 자동 삽입, 성과 자동 수집, 기존 제목과 중복 경고 | YouTube API 업로드는 앱 심사(감사) 전엔 비공개로 고정됨 → 심사 전까지는 수동 업로드 |
| 구독료 없음 (ffmpeg·Whisper·Ollama 무료) | 서버 PC 한 대에 의존 — 01·02 운영과 GPU를 나눠 씀 |

### C. B + 사람 검토 (권장)

B의 단점 중 품질·책임 문제를 **검토 화면 한 장**으로 막습니다. 자동은 초안까지, 공개는 반드시 사람 승인. 편집자 1명의 일이 "원장 촬영 + 담당자 검토 10분"으로 바뀝니다.

### D. AI 아바타·음성 합성 (촬영까지 생략)

| 장점 | 단점 |
| --- | --- |
| 원장 시간 0, 편수 무제한 | 이 채널의 자산은 **"탈모를 겪은 의사 본인"이라는 신뢰**(분석 보고서 P6: "의사가 ~" 제목 최근 중앙값 2.4만) — 합성 티가 나면 그 신뢰를 잃음 |
| | 유튜브는 사실적인 합성·변형 콘텐츠에 공개 표시를 요구 |
| | 의료 정보를 합성 인물이 말하면 의료광고·책임 문제가 커짐 |
| | 원장 얼굴·목소리 데이터 유출·악용 위험 |

→ 모발이식 상담을 만드는 채널에는 맞지 않습니다. 원장 출연 없는 **카드형 쇼츠(글자 + 이미지)**는 완전 자동이 가능하지만, 이 채널의 히트작은 모두 원장 출연형이라 실험용으로만 권합니다.

## 3. 권장안: C (반자동 자체 파이프라인)

이유:
1. 이 채널 형식이 단순해서(토킹헤드 + 자막) 자동화 효과가 큽니다.
2. 핵심 부품(Whisper, 로컬 AI, GPU 서버, 직원 로그인)이 이 리포에 이미 있습니다.
3. 분석 보고서의 해결방안(영상 코드·UTM·관련 동영상·반복 방지·표현 점검·주간 리뷰)을 **제작 흐름 안에 넣을 수 있는 건 자체 파이프라인뿐**입니다. 상용 도구로는 이 규칙들을 사람이 매번 기억해야 합니다.
4. 검토·승인 단계를 강제할 수 있어 의료광고 책임을 지킬 수 있습니다.

## 4. 구현 설계

### 4.1 전체 흐름

```
[입력 1] 원장 세로 촬영본 (폰, 한 번에 여러 편 몰아 찍기)
[입력 2] 롱폼 원본 (16:9)
      │ 업로드 (웹, 직원 로그인)
      ▼
① 분석    ffprobe 검사 → 음성 추출(16kHz) → Whisper 받아쓰기(단어별 시간) → 용어 사전 교정
      ▼
② 나누기  입력 1: "다음" 신호(박수·"넘버 N" 발화)로 편별 분할
          입력 2: AI가 30~50초 완결 구간 후보 선택 → 문장 경계에 맞춤
      ▼
③ 편집안  무음·말 더듬음·NG 컷 → 자막 줄 나누기 → 강조어 → 훅 문구 3안
          → 제목 3안·설명·해시태그 → 영상 코드(S1112 등) 부여
      ▼
④ 점검    표현 규칙 사전 + AI 2차 → 경고 / 기존 쇼츠 제목과 유사도 → 반복 경고
      ▼
⑤ 렌더    (롱폼이면 얼굴 따라 9:16 자르기) → 자막·훅·끝 화면 합성 → 음원·음량 → mp4 (NVENC)
      ▼
⑥ 검토    웹 검토 화면: 미리보기 · 자막 수정 · 컷 켜고 끄기 · 제목 선택 · 경고 해소 · 승인
      │      (수정하면 ⑤만 다시)
      ▼
⑦ 게시    1단계: mp4 + 제목·설명 복사 → Studio 수동 업로드
          3단계: YouTube Data API 예약 업로드 → 관련 동영상 연결 체크
      ▼
⑧ 측정    YouTube Analytics API 매일 수집 → 주간 표 (분석 보고서 S7) · 상담 유입(영상 코드)과 합침
```

| 용어 교정 | 사전 파일 (예: "미녹 시딜"→"미녹시딜", "피나스 테리드"→"피나스테리드") | Whisper가 자주 틀리는 의료 용어를 규칙으로 고침. 검토에서 고친 내용이 사전 후보로 쌓임(02 학습 고리와 같은 원칙: 제안만, 반영은 관리자) |

| AI (구간 선택·훅·제목·점검) | 기본 로컬 Ollama(서버 PC, 외부 전송 없음), 설정으로 Claude API 전환 | 02와 같은 방식. Claude API 선택 시 **자막 텍스트만** 전송(영상·음성 안 보냄). 4B 로컬 모델 품질이 부족하면 API 쪽이 현실적 |

| 음원 | 병원이 라이선스를 가진 트랙 폴더 (예: YouTube 오디오 보관함) | 저작권 문제 차단. 폴더 밖 음원은 쓰지 않음 |
| 로그인 | 02 출입증(JWT) 검증 — 01과 같은 방식 | 촬영본 업로드: Staff 이상, **승인: Owner·Doctor** |
| 저장 | DB: SQLite `C:\GoodMoNa\03\data\shorts.db`, 영상: `C:\GoodMoNa\03\media\` | OneDrive 밖. 롱폼 원본은 수 GB → 보관 기간 정책(예: 게시 후 90일 원본 삭제) |

### 4.3 단계별 상세

**② 촬영본 자동 분할 (입력 1)** — 원장 부담을 줄이는 핵심입니다. 대본 카드 10장을 한 번에 찍고 사이마다 "넘버 3"처럼 말하거나 박수를 칩니다. 받아쓰기에서 "넘버 N"을 찾고, 음량이 튀는 박수 지점으로 보정해서 편별로 나눕니다. 같은 카드를 다시 찍었으면(NG) 마지막 테이크를 기본으로 고르고, 검토 화면에서 바꿀 수 있게 합니다.

**② 롱폼 → 쇼츠 구간 선택 (입력 2)** — 받아쓰기 문장 목록(시간 포함)을 AI에 주고 다음 조건의 구간 후보 5개를 JSON으로 받습니다: 30~50초, 앞뒤 맥락 없이 이해됨, 첫 문장이 질문·반전·숫자. 서버는 AI가 준 시간을 **문장 경계에 맞춰 고치고**, 범위·길이를 검사합니다(02가 AI 답변의 근거 번호를 서버에서 검사하는 것과 같은 원칙 — AI 출력을 그대로 믿지 않음).

**③ 컷 편집** — 단어 사이 공백이 0.4초를 넘으면 0.15초만 남기고 자릅니다. "어", "음", "그러니까" 같은 군말은 후보로 표시만 하고 기본은 자르지 않습니다(의미가 바뀔 수 있음). 결과는 "남길 구간 목록"으로만 저장하고 원본은 건드리지 않습니다.

**③ 자막** — 한 줄 최대 12자, 두 줄까지. 문장 끝·쉼표·조사 뒤에서 나눕니다. AI가 고른 핵심어(숫자, 약 이름, "절대" 등)는 강조색. 단어별 시간으로 타이밍을 맞춥니다.

**③ 끝 화면 (분석 보고서 S2·S3)** — 마지막 2~3초에 "전체 설명은 아래 영상에서" + 영상 코드("상담 때 S1112 말씀하세요"). 설명란에는 롱폼 링크용 UTM과 영상 코드를 자동으로 넣습니다.

**④ 표현 점검 (분석 보고서 S6)** — 두 단계:
1. 규칙 사전(정규식): `최고|최초|유일|완치|100%|\d+배|부작용\s*(없|0)|노벨|무조건|절대 안|사기` 등 → 위치 표시
2. AI 2차 점검: 단정·근거 없는 수치·타 치료 폄하·경험담 여부를 문장별로 표시

경고가 남아 있으면 승인 버튼이 비활성화되고, "문제없음으로 판단 + 사유"를 적어야 넘어갑니다(기록 남음). 환자가 나오는 영상은 "출연 동의서 확인" 체크가 필수입니다.

**④ 반복 방지 (분석 보고서 P5)** — 기존 쇼츠 제목 목록(`tools/collect-shorts.js`로 받은 TSV 가져오기 + 이후 게시분 자동 추가)과 새 제목의 2-gram 유사도를 계산합니다(02의 2-gram 검색 방식 재사용). 기준을 넘으면 "비슷한 제목 N편, 최근 X일 내 Y편" 경고. 같은 핵심 키워드가 2주 안에 또 나오면 경고합니다.

**⑤ 렌더** — 미리보기용(540p, 빠름)과 게시용(1080×1920, 30fps, 음량 −14 LUFS)을 따로 만듭니다. 검토에서 자막만 고치면 자막 합성만 다시 합니다.

### 4.5 API (초안)

| 경로 | 설명 |
| --- | --- |
| `POST /api/shorts/sources` | 촬영본·롱폼 업로드 (큰 파일 → 조각 업로드) |
| `GET /api/shorts/sources/{id}` | 분석 진행 상태 |
| `GET /api/shorts/drafts?status=` | 초안 목록 |

| `POST /api/shorts/drafts/{id}/approve` | 승인 (Owner·Doctor, 경고 해소·동의 체크 검사) |

실시간 진행 표시는 01처럼 SignalR로 보냅니다(분석 중 → 초안 완성 알림).

### 4.6 화면

- **올리기**: 파일 끌어다 놓기, 종류 선택(세로 촬영본/롱폼), 진행률.
- **초안 목록**: 상태별 표 — 썸네일, 영상 코드, 제목, 경고 수, 길이.
- **검토 화면** (핵심): 왼쪽 9:16 미리보기, 오른쪽 탭 —
  - 자막: 줄 단위 표(시작·끝·글자), 고치면 용어 사전 후보로 쌓임
  - 구간: 잘린 부분 목록, 켜고 끄기
  - 제목·설명: 3안 중 선택·수정, 비슷한 기존 제목 경고
  - 점검: 경고 목록 → 해소 사유 입력, 출연 동의 체크
  - 승인 / 반려
- 디자인은 리포 규칙대로 `base.css` 토큰만(무채색 + 강조색 하나).

### 4.7 업로드 자동화 (3단계)

- YouTube Data API v3 `videos.insert`(이어 올리기 방식), 채널 소유자 OAuth 동의 → 갱신 토큰은 데이터 폴더의 로컬 설정 파일에만(리포·채팅 금지, 02의 `appsettings.local.json` 원칙).
- `status.privacyStatus=private` + `publishAt`으로 예약 게시. 세로이고 3분 이하면 쇼츠로 분류됩니다.
- **제약**: 심사(감사)를 받지 않은 API 프로젝트로 올린 영상은 비공개로 고정됩니다 → 심사 신청이 필요하고, 그 전까지는 1단계 방식(파일 받아 Studio에서 수동 업로드)을 씁니다.
- API 할당량이 정해져 있고 업로드는 비용이 큰 호출이라 하루 몇 편 수준으로 제한합니다(분석 보고서 S5 권장 편수와도 맞음). 정확한 단가는 착수할 때 공식 문서로 확인합니다.
- **관련 동영상 링크**: API로 설정할 수 있는지 확인하지 못했습니다 → 게시 후 "Studio에서 관련 동영상 연결" 체크 항목을 남기고, 연결 여부를 `Publication.RelatedVideoLinked`에 기록합니다.
