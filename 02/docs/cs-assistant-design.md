# CS 안내 도우미 설계 (LLM 위키로 CS 응대)

> 문서 묶음: [인트라넷 기능 설계](intranet-design.md) · **CS 안내 도우미 설계**(이 문서) · [02 README](../README.md)
> 작성 기준일: 2026-11-15 · 상태: 1·2·4단계 프로토타입 구현. 3단계 AI 답변은 **서버 PC 로컬 모델(Ollama, qwen3:4b-instruct)로 운영**(사용자 결정), Claude API로도 바꿀 수 있음

과제 원문의 "LLM 위키로 CS 응대"를 굿모나 행정·CS 직원용 **CS 안내 도우미**로 구체화한 설계입니다. 지금 버전은 과제 샘플이자 프로토타입입니다. 자료를 뽑아 승인하고, 직원이 찾아 쓰고, 못 찾은 질문이 다시 자료가 되는 **과정 전체**가 실제로 돌아가는 것을 목표로 했습니다.

## 1. 목표와 범위

| 구분 | 내용 |
| --- | --- |
| 쓰는 사람 | 전화·카톡·데스크에서 고객 문의를 받는 CS·행정 직원 (로그인한 모든 직원) |
| 답하는 범위 | **굿모나의원에 대해 승인된 자료만**: 진료 시간, 예약·취소, 주차, 결제·환불 안내, 서류, 시술 안내문, 원장님 영상 내용 |
| 답하지 않는 것 | 자료에 없는 내용, 일반 의학 상담, 진단·처방·시술 적합성 판단(→ "원장님 확인 필요"), 다른 병원 이야기 |
| 다루지 않는 데이터 | 환자 기록(01 DB). 질문 안의 전화번호·주민번호는 저장 전에 가림 |
| 운영 원칙 | 초기에만 클라우드 AI로 자료를 정리하고, 운영은 **내부망(서버 PC) 안에서만**. AI가 꺼져도 검색은 동작 |

## 2. 주요 결정

| 질문 | 결정 | 이유 | 버린 안 |
| --- | --- | --- | --- |
| "학습"을 어떻게? | **지식 축적**: 승인된 FAQ·문서가 쌓이고, 답할 때 그것을 찾아 읽음 | 가격·규정이 바뀌면 자료만 고치면 되고, 출처를 댈 수 있고, 틀린 자료는 내리면 끝 | 모델 재학습(파인튜닝): 바뀌는 사실을 다시 학습해야 하고 출처를 못 대며 틀려도 확신 있게 답함. 8GB GPU로는 학습도 빠듯 |
| 누가 지식을 늘리나? | **관리자 승인을 거쳐서만** | 병원 CS에서 검증 안 된 답(가격·환불)이 나가면 위험 | 에이전트가 스스로 기억·스킬을 씀(Hermes Agent 방식) |
| 초기 자료 수집 | Claude·Codex로 원문(영상 대본·안내문)을 **정해진 형식으로 정리 → 붙여넣기 → 초안 → 승인** | 사람이 하기 힘든 "모으고 정리하기"만 맡기고, 결과는 사람이 승인한 문서로 남김(모델을 바꿔도 지식은 그대로) | 클라우드 AI를 운영 답변에도 계속 사용: 질문이 외부로 나감 |
| 운영 AI | **서버 PC의 로컬 모델(Ollama + qwen3:4b-instruct)**. 2026-11-15 결정. 설정 하나로 Claude API로도 바꿀 수 있음 | 질문·자료가 서버 밖으로 나가지 않고 건당 비용이 없음. 예시 질문 10개 모두 근거 있는 답, 1초 안팎(§7). 어느 쪽이든 꺼져도 검색은 됨 | Claude·Codex **구독**을 서버 답변에 사용: 구독은 개인 사용 범위라 서버 백엔드로 쓸 수 없음(초기 자료 정리에만) |
| 검색 | **글자 2개 단위(2-gram) + BM25**, 서버 메모리 색인 | 한국어 조사("환불은")에 강하고, 병원 한 곳 자료량이면 메모리로 충분 | SQLite FTS5 trigram(세 글자 미만인 "연차·환불·주차"를 못 찾음), 벡터 DB(지금 규모엔 과함, 필요하면 4단계 이후) |
| Hermes Agent | 본체로 쓰지 않음. 관리자가 초기 자료를 정리할 때 개인 도구로 쓰는 것은 가능 | 개인용 에이전트라 다중 사용자·권한·승인·감사 기록이 없음. Python 필요 | 인트라넷 백엔드로 Hermes 사용 |

## 3. 전체 흐름

```
[초기 수집 · 1회성, 관리자]
  원장님 영상 대본(Whisper) · 기존 안내문 · 규정
     └▶ Claude/Codex에 "정리 지시문"과 함께 넣음 ─▶ Q:/A: · ## 제목 형식의 글
          └▶ 자료 관리 > 자료 가져오기 (미리 보기 → 초안) ─▶ 관리자 검토·승인

[운영 · 서버 PC 안]
  직원 질문 ─▶ 전화번호·주민번호 가림 ─▶ 승인된 자료 검색(2-gram BM25)
     ├─ 찾음  ─▶ FAQ · 안내 문서 (+ AI 켜짐: 찾은 자료만 근거로 쓴 답, 근거 번호 검사)
     └─ 못 찾음 ─▶ "관련 있을 수도 있는 자료"만 보여 주고 관리자에게 넘김

[학습 고리 · 관리자]
  처리할 질문(못 찾음·"부족함")
     ├─ 맞는 자료가 있는데 표현이 다름 ─▶ "「자료」에 표현 추가" (검색 보조어로 붙임)
     ├─ 자료가 없음 ─▶ "FAQ로 만들기" (바로 승인 가능)
     └─ 잡담·중복 ─▶ 닫기
  → 다음에 같은 질문을 하면 찾음
```

## 4. 단계별 계획과 진행

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1 | 지식 저장소(FAQ·문서), 상태(초안·승인·반려·내림), 관리자 승인, 재검토일, 2-gram 검색, CS 도우미 화면(답 복사), 직원 자료 제안 | **구현** |
| 2 | 자료 추출(규칙: `#` 제목 → 문서, `Q:`/`A:` → FAQ, `분류:`·`키워드:`), 미리 보기 → 초안 묶음, 가져오기 기록(정리한 AI 표시), AI 정리 지시문, 가상 예시 자료(`02/samples/cs-knowledge`) | **구현**. 영상 대본 자동 수집(01 Whisper 연동)은 남음: 지금은 대본 텍스트를 붙여넣음 |
| 3 | 로컬 AI 답변: Ollama 호출, 근거 번호 검사, 실패 시 검색만, 못 찾으면 AI를 부르지 않음, 모델 상주·미리 올리기 | **구현**. 서버 PC에 Ollama·qwen3:4b-instruct 설치, 예시 자료로 평가(§7). 평가 묶음 측정은 남음 |
| 4 | 학습 고리: 질문 기록, 못 찾은 질문·"부족함" → 처리할 질문, 표현 추가·FAQ로 만들기·닫기, 홈 "처리할 일"에 건수 | **구현**. 평가 묶음 자동 측정은 남음(§8) |
| 5 | (선택) 말투·형식만 맞추는 파인튜닝 | 설계만. 승인된 Q&A가 수천 건 쌓인 뒤 검토. 사실 정보는 계속 검색으로 |

## 5. 자료와 승인

### 상태

```
            직원 제안 · 가져오기 · 질문에서 만들기
                         │
                         ▼
   반려 ◀── 관리자 ── [초안] ── 관리자 승인 ──▶ [승인] ── 내리기 ──▶ [내림]
    │                                  ▲            │                 │
    └──────────── 다시 승인 ────────────┴────────────┼── 다시 승인 ─────┘
                                                   └ 고치기(고친 관리자가 다시 승인한 것으로 기록)
```

| 규칙 | 내용 |
| --- | --- |
| 검색 대상 | **승인**된 자료만. 초안·반려·내림은 검색·AI 근거에서 빠짐 |
| 누가 | 직원: 승인된 자료 보기, 자료 제안(초안), 내 제안의 결과(반려 사유) 보기. 대표원장·관리자: 가져오기, 승인·반려·고치기·내리기·지우기, 처리할 질문 |
| 바로 승인 | 관리자가 직접 쓰거나 질문에서 FAQ를 만들 때 "저장하면서 바로 승인" 가능 |
| 반려 | 초안만, 사유 필수(직원에게 보임) |
| 지우기 | 승인된 자료는 먼저 내려야 함(검색 중인 자료를 실수로 지우지 않게) |
| 재검토일 | 가격·이벤트처럼 바뀌는 자료에 날짜를 넣으면, 지난 뒤 직원 화면·관리 화면에 "재검토일 지남" 표시 |
| 출처 기록 | 직접 작성 / 가져오기(원본 이름, 정리한 방법: 직접·Claude·Codex·기타 AI) / 직원 질문(질문 번호) |

### 추출 형식

```
<!-- 메모 -->              무시 (예시 자료 표시 등)
# 큰 제목                  아래 소제목 문서들의 앞 이름 ("큰 제목 · 소제목")
## 소제목                  문서 한 건 (다음 제목 전까지가 본문)
분류: 예약                  이후 자료의 분류
Q: 질문 / A: 답             FAQ 한 건 (질문:·답:, Q1.·A1., **Q.** 도 됨, 답은 여러 줄)
키워드: 예약 변경, 노쇼      바로 앞 자료의 검색 보조어
```

제목도 Q/A도 없는 글은 통째로 문서 한 건이 됩니다(제목 = 원본 이름). 본문이 4,000자를 넘으면 문단 단위로 나눕니다. 답 없는 질문처럼 건너뛴 것은 미리 보기에 경고로 보입니다. 규칙 추출이라 같은 글은 언제나 같은 결과가 나오고, AI 비용이 들지 않습니다.

### 초기 수집 지시문 (Claude·Codex에게)

자료 관리 화면의 "형식 · AI 정리 지시문 보기"에 있는 것과 같습니다.

```
아래 자료는 굿모나의원 CS 직원이 고객 문의에 답할 때 참고할 원문입니다.
다음 형식으로만 정리해 주세요.
- 고객이 실제로 물을 법한 질문은 "Q: 질문" 다음 줄에 "A: 답"으로 씁니다.
- 질문으로 바꾸기 어려운 안내는 "## 제목" 아래 본문으로 씁니다.
- 주제가 바뀌면 "분류: 예약"처럼 분류 줄을 넣습니다.
- 고객이 다르게 말할 만한 표현은 답 아래 "키워드: …" 줄에 쉼표로 적습니다.
- 원문에 없는 내용(가격·기간·효과 등)은 절대 지어내지 말고, 원문이 애매하면 "확인 필요"라고 씁니다.
- 진단·처방처럼 의학적 판단이 필요한 내용은 "원장님 확인이 필요합니다"로 답합니다.
- 환자 이름·연락처는 쓰지 않습니다.
```

예시: `samples/cs-knowledge/raw/원장-영상-대본-예시.txt`(가상 대본)를 이 지시문으로 정리한 결과가 `samples/cs-knowledge/organized/원장-영상-정리-Claude.md`입니다. 대본을 그대로 넣으면 699자짜리 문서 한 건이 되고, 정리본을 넣으면 FAQ 5건(분류·보조어 포함)이 됩니다.

클라우드 AI의 출력은 **사람이 승인한 문서**로만 씁니다. 그 출력으로 모델을 재학습(5단계)하려면 먼저 각 회사 약관을 확인해야 합니다.

## 6. 검색

| 항목 | 내용 |
| --- | --- |
| 조각 | 소문자로 바꾸고 글자·숫자 낱말을 두 글자씩 자름. "환불은" → 환불·불은, "2시간" → 2시·시간. 한 글자 낱말은 그대로 |
| 질문 끝말 | "나요·인가·어떻·떻게·예요…" 같은 조각은 질문 쪽에서만 뺌(일치 비율이 낮아지지 않게) |
| 점수 | BM25(k1 1.2, b 0.75). 제목·검색 보조어는 두 번 셈 |
| 찾음 기준 | 질문 조각의 **40% 이상**이 들어 있는 자료. 정렬은 일치 비율(0.1 단위) → 점수 |
| 결과 | FAQ 최대 3, 문서 최대 5. 더 잘 맞는 쪽을 위에 보여 줌. 못 찾으면 조금이라도 겹친 자료 3개를 "관련 있을 수도 있는 자료"로 |
| 색인 | 승인된 자료로 서버 메모리에 만들고, 자료가 바뀌면 버렸다가 다음 검색 때 다시 만듦 |

**예시 자료로 잰 결과** (가상 자료 16건, 2026-11-15, 개발 서버):

| 질문 | 결과 |
| --- | --- |
| 주차 몇 시간 무료예요? · 주차비 | 찾음: 진료 안내 · 주차 |
| 토요일에도 진료해요? · 점심시간 언제예요 | 찾음: 진료 시간 · 점심시간 |
| 예약 취소하고 싶어요 · 환불 되나요 · 실비 청구 서류 뭐 필요해요 | 찾음: 해당 FAQ |
| 시술하고 세수해도 돼요? | 찾음: "시술 받고 바로 세안해도 되나요?"(일치 0.43, 영상 정리본의 보조어 "세수" 덕분) |
| 가격 얼마예요 | 찾음: 진료 안내 · 결제 (전화로는 범위만 안내) |
| 영수증 발급 | 찾음: "실비 보험 청구 서류는…" FAQ(일치 0.67) |
| 시술 부위가 빨개졌어요 | **못 찾음**(0.33). 맞는 FAQ가 "관련 자료" 첫 줄에 보임 → 관리자가 "표현 추가"로 해결 |
| 고객님이 늦는대요 | **못 찾음**. "늦는대요"와 보조어 "늦음·늦어요"의 활용형이 달라 놓침 → 표현 추가 |
| 보톡스 효과 얼마나 가요 | **못 찾음**(자료 없음, 맞는 동작) → 관리자가 FAQ로 만들거나 "원장님 확인"으로 닫음 |

13개 중 10개를 찾았습니다. 못 찾은 3개 가운데 2개는 맞는 자료가 있는데 활용형이 달라 놓친 경우입니다. 이런 질문이 관리자에게 모이고 표현을 붙이면 다음부터 찾게 되도록 만든 것이 학습 고리입니다. 놓침이 많아지면 4단계 평가로 측정한 뒤, 로컬 의미 검색(임베딩)을 더하는 것을 검토합니다.

## 7. AI 답변 (3단계, 운영: 로컬 모델)

| 장치 | 내용 |
| --- | --- |
| 근거 범위 | 검색이 찾은 자료 중 상위 4건(`MaxPassages`)만 [1]~[4] 번호를 붙여 넘김. 못 찾으면 **AI를 부르지 않음** |
| 지시 | 자료에 있는 것만, 없으면 "자료에 없음", 의학적 판단은 "원장님 확인이 필요합니다", 문장마다 [번호], 존댓말 3~5문장 (`Knowledge/Assistant.cs`의 `AnswerPrompt`) |
| 서버 검사 | 답에 근거 번호가 하나 이상 있고 모두 넘긴 자료 번호여야 통과(`AnswerCheck`). 아니면 버리고 검색 결과만 보여 줌 |
| 장애 | 연결 실패·시간 초과(기본 60초)면 "AI 답변을 지금 쓸 수 없어 찾은 자료만 보여 드립니다" |
| 화면 | 답 아래 근거 링크([1] 누르면 해당 자료로 이동), "응대 문구 복사"는 근거 번호를 빼고 복사 |
| 외부 전송 | Claude 모드: **가린 질문 + 찾은 자료 최대 4건**이 Anthropic API로 감(환자 기록·직원 정보는 보내지 않음). Ollama 모드: 없음(localhost만) |
| 교체 | AI 호출은 `IAnswerWriter` 하나로만 함: `NoAnswerWriter`(꺼짐) · `ClaudeAnswerWriter`(공식 Anthropic C# SDK, 기본 모델 claude-opus-5-5, effort low, 거절 시 서버 측 대체 모델) · `OllamaAnswerWriter`. 설정 `App:Assistant:Mode` 하나로 바꿈 |

### 켜는 방법: 로컬 모델 (운영안)

1. 서버 PC에 Ollama를 설치하고 모델을 받습니다: `ollama pull qwen3:4b-instruct` (2.5GB, Apache 2.0 — 상업 사용 가능, 한국어 지원, 생각 단계 없는 지시형). `OLLAMA_HOST`를 바깥 주소로 열지 않습니다(localhost:11434만).
2. `powershell -ExecutionPolicy Bypass -File 02\deploy\set-assistant.ps1 -Mode Ollama -Model qwen3:4b-instruct`를 실행합니다(UAC "예").
   - 데이터 폴더(`C:\GoodMoNa\02\data`)의 `appsettings.local.json`에 `App:Assistant`를 쓰고 `GoodMoNa02`를 다시 시작합니다. 설치 폴더의 설정은 배포 때마다 새로 써지므로 여기에 둡니다.
   - 끄려면 `-Mode Off`.
3. CS 도우미 화면 위에 "AI 답변 켜짐"이 보이면 됩니다.

**첫 질문 지연 대책**: Ollama는 기본으로 5분 동안 질문이 없으면 모델을 GPU에서 내립니다. 다시 올리는 데 처음(디스크에서 처음 읽을 때)은 1분 넘게 걸려 제한 시간(60초)을 넘겼습니다. 그래서
- 요청마다 `keep_alive`(`App:Assistant:KeepAlive`, 기본 `-1m` = 계속 올려 둠)를 보내 모델을 GPU에 상주시킵니다(약 3.2GB).
- 서버가 켜질 때 `OllamaWarmup`이 모델을 미리 올립니다(실패하면 1분 간격으로 5번까지 다시 시도).
- Ollama는 **사용자 로그인 시 실행되는 앱**입니다. 서버 PC를 재부팅하면 로그인할 때까지 AI 답변 없이 검색 결과만 나갑니다.

### 측정 (2026-11-15, 개발 서버, 예시 자료 16건 승인)

| 항목 | 결과 |
| --- | --- |
| 근거 검사 통과 | 질문 10개 중 **10개** (주차·토요일 진료·예약 취소·실비 서류·시술 후 세안·가격·환불·영수증·점심시간·주차비) |
| 응답 시간 | 모델이 올라가 있으면 **0.2~0.7초**. 미리 올리기 전에는 첫 질문 60초 초과(시간 초과 → 검색 결과만), 미리 올린 뒤 첫 질문 3초 |
| 내용 | 모두 자료 범위 안. "시술하고 세수해도 돼요?"는 "시술 종류와 관련이 있습니다"처럼 말이 조금 어색했지만 자료 내용(안내문을 따르고 없으면 데스크 연락)은 맞음 |
| GPU | 모델 3.2GB 전부 GPU. Whisper(약 2.5GB)와 합쳐 약 5.7GB로 8GB 안에 들어감 |

예시 자료는 짧아서 실제 자료보다 쉽습니다. 실제 자료로 평가 묶음(§8)을 만들어 다시 잽니다.

### 켜는 방법: Claude API (대안)

1. platform.claude.com 콘솔에서 API 키를 만듭니다(사용자가 직접). Claude·Codex **구독**은 쓸 수 없습니다.
2. `powershell -ExecutionPolicy Bypass -File 02\deploy\set-assistant.ps1 -Mode Claude`를 실행합니다. UAC "예"를 누른 뒤, 열린 관리자 창에 키를 붙여넣습니다(화면에 안 보임). 키가 든 파일은 SYSTEM·Administrators만 읽게 권한을 줄입니다. 모델을 바꾸려면 `-Model <모델 ID>`.
3. 비용: 질문 1건에 입력 약 2천~8천, 출력 수백 토큰이면 claude-opus-5-5(100만 토큰당 입력 $4·출력 $20)로 대략 $0.01~0.05(측정값 아님). 자료를 찾은 질문에만 호출합니다.

### GPU 제약

서버 PC는 **RTX 2080 8GB**이고, 01의 Whisper(녹음 변환)와 함께 씁니다. 그래서 7~8B(약 5GB 이상) 대신 **4B 모델**을 골랐습니다.
- **겹칠 때**: AI 답변이 늦으면 시간 초과로 검색 결과만 나가므로 업무는 멈추지 않습니다.
- **근본 대책**: 더 큰 모델이 필요해지면 VRAM 16GB 이상 GPU로 바꾸거나 AI 전용 PC를 둡니다.

## 10. 시연 순서 (과제 샘플)

1. 대표원장으로 로그인 → **자료 관리**(`/intranet/knowledge`).
2. "형식 · AI 정리 지시문 보기"로 지시문을 확인합니다. `samples/cs-knowledge/raw`의 대본이 지시문으로 `organized/원장-영상-정리-Claude.md`가 된 것을 보여 줍니다.
3. 자료 가져오기에서 파일 `organized/진료-안내.md`를 고릅니다 → 미리 보기(6건) → **초안으로 가져오기**. 나머지 두 파일도 가져옵니다(정리한 방법: Claude).
4. 승인 대기에서 펼쳐 확인 → 모두 선택 → 승인.
5. 직원 계정으로 **CS 도우미**(`/intranet/ask`) → "주차 몇 시간 무료예요?" → 자료가 나오고 "답 복사".
6. "시술 부위가 빨개졌어요" → 못 찾음, 관련 자료 표시 → "관리자에게 전달".
7. 관리자 홈의 처리할 일 "CS 자료 · 질문" → 자료 관리 → **「시술 후 빨갛게…」에 표현 추가**.
8. 직원이 같은 질문을 다시 하면 찾습니다.
9. (AI를 켰다면) 같은 질문에 근거 번호가 달린 AI 답변이 위에 나옵니다.

## 11. 위험과 남은 일

| 위험 | 대응 |
| --- | --- |
| 승인 안 된 내용·지어낸 답이 고객에게 감 | 승인된 자료만 검색, AI는 근거 번호 검사, 못 찾으면 AI 미호출, 의학적 판단은 원장 확인 |
| 가격·이벤트 정보가 낡음 | 재검토일 표시, 관리 화면에서 지난 자료를 위로 |
| 활용형 차이로 못 찾음 | 처리할 질문 → 표현 추가. 평가에서 많으면 의미 검색 추가 |
| GPU를 Whisper와 함께 씀 | 4B 모델(3.2GB) 상주, 시간 초과 시 검색만, 필요하면 GPU 교체 |
| 서버 재부팅 뒤 Ollama가 안 뜸 | Ollama는 로그인 시 실행 — 그동안은 검색만. 무인 재부팅이 잦으면 Ollama를 서비스로 등록 검토 |
| 질문에 환자 정보가 섞임 | 화면 안내 + 전화번호·주민번호를 저장·전송 전에 가림. 이름은 가리지 못하므로 안내로 막음(Claude 모드에서는 외부로 나갈 수 있음) |
| API 키 유출 | 리포·설치 폴더에 두지 않고 데이터 폴더 파일에만, SYSTEM·Administrators만 읽기. 키를 채팅에 붙여넣지 않음 |
| 관리자가 처리할 질문을 쌓아 둠 | 홈 "처리할 일"에 건수 표시. 운영 지표로 쌓인 날 수 확인 |

남은 일: 실제 자료로 평가 묶음 측정(로컬 모델 정확도), 01 Whisper 대본을 바로 가져오는 경로, 자료 수정 이력(지금은 마지막 수정자만), 비슷한 질문 묶어 보기.
