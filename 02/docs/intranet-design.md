## 1. 과제 이해와 범위 결정

과제 원문은 "기본 인트라넷 형태 + 연차 관리 + 차 관리 + LLM 위키로 CS 응대"입니다. 해석이 갈리는 부분은 사용자(과제 수행자)와 확인해 아래처럼 정했습니다.

| 원문 | 결정 | 다른 해석과 고르지 않은 이유 |
| --- | --- | --- |
| 기본 인트라넷 형태 | 공지(필독·읽음 확인) · 주소록 · 출퇴근 기록 + 홈 대시보드 | 사내 메신저(SignalR)·품의/결재는 2차로 미룸. 공지·주소록은 작업량 대비 매일 쓰임이 크고, 출퇴근은 연차(출근율)와 이어짐 |
| 연차 관리 | 근로기준법 제60조 자동 계산, **입사일 기준**, 신청 → 승인, 팀 달력 | 회계연도(1/1) 기준은 관리가 편하지만 중도 입사자 비례 계산·퇴사 정산이 필요해 분쟁 소지가 큼. 법 원칙인 입사일 기준을 택함 |
| 차 관리 | **직원 주차**: 차량 등록 · 배정 신청 → 주차면 배정 · 번호로 차주 찾기 | 병원 업무 차량(예약·운행일지)이나 환자 주차 할인 등록도 후보였음. 환자 주차는 주차 관제 업체 연동이 필요해 CRM처럼 설계만 될 가능성이 커서 제외 |
| 근무 요일 | 월~금 기본, 설정에서 변경 | 토요일 진료 병원은 설정으로 토요일을 켬. 직원별 근무 요일(파트타임)은 2차 |

## 2. 구조

01과 같은 스택(.NET 10 Minimal API · EF Core SQLite · Vite + TypeScript)을 그대로 씁니다. 새 서버를 만들지 않고 02 서버에 붙였습니다 — 직원 DB가 02에 있어 연차·출퇴근·주차가 모두 직원과 묶이기 때문입니다.

```
브라우저 ── https://goodmona.hsdevs.com/intranet/* , /api/intranet/*
   │ Cloudflare 터널 경로 규칙: /intranet* · /api/intranet/* → 02 (01/deploy/install.ps1의 $intranetPaths)
   ▼
GoodMoNa02.Server
   Endpoints/  Home · Notice · Leave · Attendance · Parking · Settings      ← 라우트 그룹 /api/intranet (로그인 필수)
               관리 기능은 엔드포인트마다 RequireAuthorization(ManageStaff = 대표원장·관리자)
   Intranet/   LeavePolicy (법 규칙, 순수 함수) → LeaveLedger (DB에서 사용·대기·조정을 모아 잔여)
               WorkCalendar (근무 요일 + 휴무일) · KoreanHolidays · ClinicSetup · AttendanceCodes · Plates
   Data/       Notice · NoticeRead · LeaveRequest · LeaveAdjustment · Holiday · ClinicSettings(한 줄)
               AttendanceRecord · Vehicle · ParkingSpot · ParkingAssignment · ParkingRequest
```

설계 원칙

1. **계산 규칙은 순수 함수로**: 연차 발생(`LeavePolicy`)과 근무일 계산(`WorkCalendar`)은 DB·시계에 기대지 않아 날짜 경계 사례를 표 형식 테스트로 검증합니다.
2. **일수는 저장하지 않고 계산**: 휴가 일수를 신청 때 저장하면, 나중에 임시공휴일·휴진일을 추가했을 때 잔여가 틀어집니다. 신청에는 날짜·단위만 두고 매번 현재 달력으로 셉니다.
3. **"누가·언제·왜"를 남김**: 승인·반려·취소·출퇴근 수정·연차 조정·주차 배정 모두 처리자 이름과 시각(필요하면 사유)을 기록합니다.
4. **직원은 지우지 않음**: 업무 기록이 직원을 참조하므로(FK Restrict) 퇴사는 "사용 중지"로만 처리합니다.

## 3. 연차

### 3.1 법 규칙 (근로기준법 제60조)

| 조항 | 내용 | 구현 |
| --- | --- | --- |
| §60① | 1년간 80% 이상 출근 시 15일 | 근속 1년 이상 기간 첫날에 15일 |
| §60② | 계속 근로 1년 미만(또는 80% 미만)은 1개월 개근 시 1일 | 입사일과 같은 날마다 1일, 최대 11일 |
| §60④ | 3년 이상 근속 시 최초 1년을 넘는 근속 2년마다 1일 가산, 한도 25일 | `15 + (근속연수 − 1) / 2`, 최대 25 |
| §60⑦ (2020 개정) | 1년 미만 월차의 사용 기간은 입사 1년이 되는 날까지 | 1년 미만 기간 = 입사일 ~ 1주년 전날 |

출근율 80%는 출퇴근 기록으로 자동 판단하지 않았습니다. 출퇴근은 이번에 도입되어 과거 기록이 없고, 휴업·육아휴직 등 출근으로 보는 기간의 법적 처리가 복잡하기 때문입니다. 미달 직원은 관리자가 조정(−)으로 반영합니다.

### 3.2 잔여 계산

```
연차 기간 = [입사 기념일, 다음 기념일)          ← 그날이 속한 기간 (LeavePolicy.PeriodOf)
발생      = 1년 미만: 기준일까지 지난 개월 수 (최대 11) / 1년 이상: AnnualDays(근속연수)
조정      = 적용일이 그 기간에 있는 LeaveAdjustment 합
사용      = 승인된 "연차" 신청 중 그 기간에 속한 근무일 (반차 0.5)
대기      = 승인 대기 "연차" 신청의 같은 계산
남은 연차 = 발생 + 조정 − 사용        쓸 수 있는 연차 = 남은 연차 − 대기
```

- 신청 검사: 쓸 수 있는 연차(대기 포함) 이내. 1년 미만은 기준일을 **휴가 마지막 날**로 잡아, 그때까지 생기는 만큼만 쓸 수 있습니다(당겨 쓰기 없음).
- 승인 검사: 다른 대기 건과 무관하게 남은 연차(승인 기준) 이내인지 다시 확인 — 신청 후 다른 휴가가 먼저 승인된 경우를 막습니다.
- 한 신청이 두 연차 기간에 걸치면 나눠서 신청하게 합니다(기간마다 잔여가 달라서).

### 3.3 대안 비교

| 항목 | 고른 것 | 대안 | 판단 |
| --- | --- | --- | --- |
| 기준일 | 입사일 | 회계연도(1/1) | 법 원칙과 일치, 분쟁·퇴사 정산 단순 |
| 공휴일 | 내장 목록(2026~27) + 관리자 추가·삭제 | 공공데이터포털 특일 정보 API | API 키·외부 호출이 필요하고 임시공휴일은 어차피 확인이 필요. 내장 목록은 한 번만 채우고, 관리자가 지운 날은 다시 생기지 않음 |
| 승인 단계 | 1단계(대표원장·관리자) | 부서장 → 대표원장 다단계 | 의원 규모에 맞춤. 품의·결재를 만들 때 다단계 승인 흐름으로 일반화 예정 |
| 반차 | 오전·오후 0.5일 | 시간 단위 연차 | 법적 의무가 아니고 계산·표시가 복잡. 필요하면 단위 enum만 늘리면 됨 |
| 진료 공백 경고 | 같은 직무가 N명(기본 2) 이상 쉬는 근무일 표시 | 신청 자체를 막기 | 막으면 급한 사정을 처리 못 함. 표시만 하고 승인자가 판단 |

## 4. 출퇴근

### 4.1 "병원에 있는지" 확인

| 방법 | 동작 | 장점 | 한계 |
| --- | --- | --- | --- |
| **병원 네트워크** | 접속 IP(Cloudflare `Cf-Connecting-IP`)가 설정의 공인 IP·CIDR 안이면 통과 | 직원은 버튼만 누름 | 공인 IP가 바뀌는 회선이면 다시 등록 필요. 폰이 LTE면 통과 못 함 |
| **입구 QR** | 입구 태블릿의 키오스크 화면이 30초마다 바뀌는 코드(HMAC-SHA256)를 QR로 표시 → 폰으로 찍으면 `/intranet/attendance?code=…` | IP와 무관, 사진을 찍어 보내도 1분 안에 무효 | 입구 태블릿이 관리자 계정으로 로그인돼 있어야 함(아래 위험) |
| 확인 끔(기본) | 어디서든 기록, "확인 없음"으로 표시 | 도입 첫날부터 사용 | 위치를 보장하지 않음 |

고르지 않은 방법

- **GPS(위치 권한)**: 실내 오차가 크고, 위치는 민감정보라 동의 절차가 필요하며 위조 앱으로 쉽게 속일 수 있음.
- **와이파이 SSID·BSSID 확인**: 웹 브라우저는 접속한 와이파이 이름을 읽을 수 없음(네이티브 앱 필요).
- **고정 QR 인쇄물**: 한 번 찍은 사진으로 어디서든 출근 가능 → 30초마다 바뀌는 코드로 대체.
- **지문·얼굴 인식 단말기**: 생체정보 처리 동의·보관 의무가 크고 장비 비용이 듦. 이미 단말기가 있으면 CSV 가져오기로 연동하는 편이 나음.

### 4.2 규칙

- 직원·날짜(병원 시간대)마다 기록 하나. 출근은 한 번, 퇴근은 다시 누르면 마지막 시각으로.
- 자정을 넘긴 퇴근은 16시간 안의 전날 출근 기록에 붙임.
- 지각 = 근무 시작 1분 이후 출근(오전 반차면 따지지 않음), 조퇴 = 근무 끝 전 퇴근(오후 반차면 따지지 않음).
- "기록 없음"은 계정을 만든 날과 입사일 중 늦은 날 이후의 지난 근무일만 — 도입 전 날짜가 결근으로 보이지 않게.
- 관리자 수정은 사유 필수, 원래 방식 대신 "관리자 수정"으로 표시.

### 4.3 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 입구 태블릿이 관리자 계정으로 로그인돼 있어 다른 화면을 열 수 있음 | 태블릿을 브라우저 키오스크 모드(전체 화면, 주소창 없음)로 운영. 2차에서 "키오스크 전용 기기 토큰"(QR만 볼 수 있는 권한)으로 분리 예정 |
| QR 사진을 받아 1분 안에 밖에서 출근 | 30초 주기·직전 코드까지만 허용으로 창을 최소화. 완전히 막으려면 병원 네트워크 확인과 함께 사용 |
| 출퇴근 기록은 근로시간 분쟁의 근거가 됨 | 수정 이력(누가·언제·왜)을 남기고, 원래 기록 방식을 표시 |

## 5. 직원 주차

| 결정 | 이유 |
| --- | --- |
| 차량은 본인이 등록(최대 3대), 번호는 공백·하이픈을 뺀 형태로 저장·유일 | 이중 주차 연락 때 번호로 바로 찾기 위해. 형식 검사로 오타 방지 |
| 배정 = 주차면 + 기간(끝 날짜 선택) | "월 주차권"·"계속 사용" 둘 다 표현. 같은 주차면·같은 직원의 기간 겹침을 서버에서 막음 |
| 신청 → 배정 | 주차면이 부족한 병원에서 대기 순서(신청일)를 공정하게 |
| 번호 뒤 4자리 검색 → 차주 연락처 | 이중 주차가 가장 잦은 실제 문제. 로그인한 직원에게만 보이고, 등록 화면에 공개 범위를 안내 |

## 6. 공지 · 주소록 · 홈

- 공지: 대표원장·관리자가 작성. **필독**은 홈 맨 위에 고정, 열면 읽음 처리. 작성자는 안 읽은 사람 목록을 봄. 필독 공지의 **내용**을 고치면 다시 확인받고(제목만 고치면 유지).
- 주소록: 사용 중인 직원만. 입사일은 대표원장·관리자에게만. 본인은 부서·연락처만 고침.
- 홈: 확인 안 한 필독 공지 · 오늘 출퇴근(바로 출근/퇴근) · 쓸 수 있는 연차와 기한 · 오늘 휴가자 · 최근 공지 · (관리자) 가입 승인·휴가 승인·주차 배정·입사일 미등록 건수.
